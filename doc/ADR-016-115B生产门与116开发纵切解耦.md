# ADR-016：115B 生产门与 116 开发纵切解耦

## 状态

已接受，2026-08-25 起生效。

## 背景

阶段 115A 已实现 cloud 三角色 Release lifecycle、Calibration v3、Production Admission builder 与默认关闭的 activation channel。真实 115B 仍需要外部事实：Candidate/Judge Provider 与 model、代码出站授权、费用预算、两名真人评审/仲裁以及 Release 有效期和激活人。

这些事实是生产 cloud 激活的合法前提，但不是实现 Codex 类本地长循环运行时的技术前提。若把全部阶段 116 都阻塞在这些外部授权之后，项目会继续等待生产治理输入，无法验证用户最关心的持续对话、多 Agent 调查、修改、测试、修复和交付闭环。

## 决策

将原顺序 `115 → 116 → 117` 拆成：

```text
115A Release / Calibration / Admission 代码底座（已完成）
  → 116A 受控编码工具面（立即实施）
  → 116B 持久多 Agent 编码循环（立即实施）
  → 115B 真实 cloud capture / 真人评审 / Production Admission（待外部授权）
  → 116C 真实模型黄金任务与生产质量验收
  → 117 Edge + 记事本安全纵切
```

116A/116B 在 `codex/stage-116-dev` 上开发，使用已通过门禁的 LOCAL-only Agent、Fake/固定测试 Provider 和隔离测试仓库证明运行时语义。它们不得生成或消费生产 Admission，不得激活 cloud-only 2.0.0 cohort，也不得把合成结果解释为真实模型质量。

115B 继续作为不可绕过的生产激活门。116C 中涉及真实模型成功率、真实 cloud cohort、Production Admission 和桌面端真实模型闭环的验收必须等待 115B 完成。

## 116A/116B 的开发完成口径

在没有 115B 外部授权时仍可实现并自动验证：

1. 同一会话的新消息可封存旧 generation/lease，并以不可变新计划代继续；
2. 至少两个独立只读 Child 并行调查，根 Agent 只消费 verified ResultRef join；
3. 多文件 Patch、固定 Test、有限 Repair、独立 Verify 和证据交付形成一个持久循环；
4. 关闭窗口、断线和 API/sidecar 重启后可从持久真值续接；
5. 写入、依赖安装和 Git 操作在 outcome unknown 时不透明重放；
6. 所有越界路径、未授权网络、未审批写入和 false-success 继续零容忍。

开发门通过只证明运行时、工具和安全语义成立，不证明 cloud 模型达到生产质量。

## 115B 仍然需要的外部授权

以下项目不推断、不代填、不由 Judge 或自动化替代：

1. Candidate 与独立 Judge 的 Provider/model；
2. 允许的数据分类与代码出站范围；
3. 总费用和单请求预算；
4. 两名真人主审及必要仲裁安排；
5. Release 有效期与 production activation actor。

在五项授权闭合前，cloud-only cohort 必须保持 disabled，115B 和 116C 不得标记完成。

## 2026-08-29 补充：个人预发布不是 Production Admission

依据 [ADR-017](ADR-017-Responses多Provider兼容与个人预发布门.md)，项目新增了 `personal_preview` 证据层，供个人开发者用一名 operator 真人评审短期检查公开合成数据。该层最长有效 14 天，固定 `activates_runtime=false`，不生成 Agent Admission，也不解锁 cloud cohort 或 116C-B。

本 ADR 第 4 项生产要求没有放宽：Production 仍须每个样本两名独立 primary reviewer，只有两人分歧时才需要第三名 arbiter。新增 Responses adapter 与三家 Provider 离线 mock 也不构成真实 capture、费用授权或厂商兼容性签发。

## 后果

- 项目立即把工程注意力转回用户可感知的 Codex 纵向切片，不再空等外部授权。
- 生产安全边界不放宽；只是把“能开发运行时”和“能激活真实 cloud Agent”分成两个门。
- 阶段编号不重排，避免破坏既有文档和不可变 baseline；以 116A/116B/116C 的门禁边界表达依赖。
- 117 继续后置，直到 116C 证明真实仓库长循环达到发布门槛。

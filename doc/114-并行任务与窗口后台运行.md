# 阶段 114：并行任务与窗口后台运行

## 1. 结果

阶段 114 已把前端的单任务活动投影升级为三槽位任务集合，并把本地 FastAPI/Runner 后端冻结成由 Tauri 监督的固定 sidecar。三个任务可同时保持独立事件连接、cursor、未读、预算、待审批、待输入和待对账状态；切换界面焦点不会 reset 或断开其他任务。

关闭主窗口现在默认隐藏到托盘，不终止本地后端或活动任务。托盘展示最多 `3 / 3` 活动任务和脱敏后端状态，可恢复窗口或执行明确退出。明确退出会停止 supervisor/sidecar；下次启动时，前端从持久任务真值中恢复最新的三个未完成任务，并从各自 cursor 重连。

## 2. 按 Task ID 隔离的运行集合

`useTaskRuntimeCollection` 在 Vue `setup` 期间同步创建三个完整 runtime slot。每个 slot 独立拥有：

- Task snapshot 和基于事件的派生状态；
- `useTaskEvents` 连接、认证重建、重连退避和持续 cursor；
- `useTaskControl`、`useTaskApproval` 和 `useTaskReconciliation`；
- 最后已读序号、未读数、待输入事件和按 `model.usage` 事件累加的 token 用量。

新任务优先进入空 slot；只有终态 slot 可回收，不会因为切换焦点而替换正在运行的 Task。第四个活动任务会在 UI 边界被明确拒绝。补偿任务和从历史打开的任务也经同一容量规则，不存在第二套隐式活动上下文。

启动恢复调用有界的任务列表 API，只选取 `created / classifying / running / waiting_approval / waiting_reconciliation / paused` 状态中最新的三项。三个真实 `useTaskEvents` 测试同时挂载三条流，证明断线后各自从不同 cursor 恢复。

## 3. exact Task/revision 控制

`pause / resume / cancel` 的请求 Schema 现在强制 `expected_last_event_seq`，并禁止额外字段。服务端在任何状态转移之前比对 exact Task ID 与事件 revision：

- 缺少请求体或 revision 以 `428 TASK_REVISION_REQUIRED` fail closed；
- stale revision 以 `409 TASK_REVISION_CONFLICT` 拒绝，不执行状态转移；
- 成功事件保存请求绑定的 revision，前端每次从当前 Task snapshot 取值；
- 响应丢失后仍按原有规则重读真值，不盲目重放 Resume。

Approval 继续使用已持久的 `approval_id → task_id` 与不可变 `preview_hash` 精确绑定，响应路径再校验 Task ID。没有为了阶段指标改变已经能拒绝跨 Task/stale preview 的 Approval replay 语义。

## 4. 冻结 sidecar 与监督边界

`backend/src/deskpilot/sidecar.py` 是 PyInstaller 固定入口。它只在 `127.0.0.1:8000` 启动单 worker Uvicorn，并在冻结子进程模式中只允许已知 Runner service/worker 与内置只读 MCP server。`build-sidecar.mjs` 使用当前 frozen `uv` 环境、固定 PyInstaller 参数和源码/锁文件时间指纹，产生 Tauri `externalBin` 所需的 host-triple sibling 文件。二进制和中间构建物不进入 Git。

Rust `SidecarSupervisor` 只解析桌面可执行文件同目录的固定 sidecar 名称，清空继承环境后只回填有限系统变量和固定 DeskPilot 安全开关。默认使用本地事件 transport，cloud admission 和 research 均关闭。意外退出最多退避重启三次；托盘只显示脱敏状态，不显示 PID、exit code、路径或凭据。明确退出回收 sidecar 进程树。

冻结 sidecar 已从实际生成的独立二进制启动，`/api/v1/health` 返回 API `ok` 且 Runner `ready / generation=1`，然后通过 Ctrl+C 干净关闭 API/Runner，不是只验证 import 或构建成功。

## 5. 托盘、窗口和恢复语义

Tauri 主窗口的 `CloseRequested` 始终被拦截并隐藏。托盘双击或“打开 DeskPilot”会 show/unminimize/focus 主窗口；“明确退出”先停 supervisor，再退出应用。Vue 仅在 Tauri runtime 内调用 `update_active_task_count`，并把计数限制在 `0..3`；普通浏览器不调用桌面 IPC。

该边界不是 Windows Service。关闭窗口后可以后台继续，但明确退出、用户注销、机器关机或重启后不会无人值守执行。下次启动只依靠已有持久 checkpoint 恢复，不会从前端内存猜测任务状态。

## 6. UI 预检

新的后台任务栏保留现有冷色仪器面板视觉，所有新增颜色均经命名 token 使用，焦点轮廓复用全局高对比样式，任务卡在小屏上从 3 列降为 2 列和 1 列，touch target 超过 44px。不支持 hover 的设备不套用 hover 样式，且没有使用缺少键盘箭头操作的伪 tablist 语义。

Finesse 静态检测器报告的两个 P0 均经人工核对为跨文件误报：Vue `:poster="coverPoster"` / `:src="coverVideo"` 变量被当成相对文件名，实际 PNG/MP4 均存在于 `frontend/public/media`；页面 GSAP 引擎位于 `App.vue`，而 build stamp 位于 `style.css`，检测器逐文件分析时无法关联二者。CSS 的大量历史字面颜色是已有全页样式债务，本阶段新组件未继续扩大该债务，也未为功能阶段执行无关的全站换色。

本阶段没有自行打开窗口作视觉断言；UI 结论限定为静态预检、类型检查和组件测试。

## 8. 仍然不是什么

- 不是 Windows Service，不在用户明确退出或机器重启后无人值守执行；
- 不允许前端突破三个活动任务容量，也不允许 stale Task/revision 控制；
- 不把托盘状态、UI 点击或 sidecar 进程存活当成任务正确性证明；
- 不开放任意 Shell、Git 写操作、联网安装、登录态浏览器或桌面应用操作；
- 安装包尚未加入产品代码签名和可信更新链。

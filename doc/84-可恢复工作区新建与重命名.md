# 阶段 84：可恢复工作区新建与重命名

阶段 84 为统一对话 Agent 增加两条 R1 工作区写入 Route：创建一个当前不存在的受限 UTF-8 文件，以及把一个现有受限文件原子重命名到当前不存在的目标。两者都先在原对话中展示版本绑定预览，只有用户明确确认后才提交；拒绝、修改任务或不操作都不会改变工作区。

本阶段不是文件管理器，也没有开放任意文件系统写权限。目录创建、覆盖、删除、隐藏路径、绝对路径、`..`、reparse point、未知扩展、跨工作区路径和自由 Shell 继续禁止。

## 1. 对话 Route

固定语法：

```text
新建工作区文件："notes/todo.md" 内容："第一项"
将工作区文件 "notes/todo.md" 重命名为 "notes/done.md"
```

对应 Route/Capability 为：

- `workspace_file_create@1` → `workspace.file.create.v1`；
- `workspace_file_rename@1` → `workspace.file.rename.v1`。

两条 Route 都绑定原始用户消息、规范化参数、静态 Route manifest、Contract、Plan 和最终结果摘要。创建内容最多 256 KiB，必须是 UTF-8；父目录必须已经存在。目标在预览或提交时已存在都会 fail closed，绝不覆盖。

## 2. 一个版本绑定的路径操作协议

`WorkspacePathOperationPreview` 统一承载创建和重命名：

- 创建绑定目标路径、目标父目录版本、拟写内容摘要、字节数和完整内容；
- 重命名绑定源路径、源文件版本、目标路径、目标父目录版本、内容摘要和字节数；
- `confirmation_digest` 覆盖任务、操作、全部路径、版本与内容证明。

提交时重新解析真实路径并复核所有绑定。外部编辑、目录变化、目标竞争、符号链接或证明漂移都会拒绝，不会尝试“尽量完成”。重命名使用 Windows 同卷非覆盖原子 rename；内容不重写，因此结果版本必须与源版本身份完全一致。

## 3. 创建的崩溃恢复

创建先把拟写字节写入 Artifact staging volume 的任务专属文件，`fsync` 后写入不可变意图清单。清单不保存额外权限，只绑定预览字段和摘要。随后使用同卷 Windows rename 把 staged file 原子发布到 Conversation Workspace。

若进程在原子边界后、数据库回执前中断，重启会同时核验：

1. 任务专属意图清单仍与原预览完全一致；
2. 目标文件的规范路径、内容摘要和字节数与预览一致；
3. Route 仍处于同一受 fence 保护的运行状态。

全部成立才重建同一 `WorkspacePathOperationReceipt`。目标文件单独出现不能冒充本次成功。原子边界前的重试复用相同 staged bytes；不同内容或不安全 staging 会阻断。

重命名恢复依赖更强的文件身份证明：源消失、目标出现且目标 `version_digest` 与预览绑定的源版本完全相同，才可恢复回执。源和目标同时缺失、目标内容不同或目标原先已存在都进入明确失败，不透明重放。

## 4. 对话确认与证据

前端继续使用统一“对话历史 + 当前 Run + 证据册”，没有新增表单式文件管理页面。R1 卡片固定回答：

- 要做什么：创建一个文件，或只改变一个文件的相对路径；
- 影响什么：目标、字节数、无目录创建、无覆盖；
- 凭什么：父目录版本、源版本或拟写内容摘要、确认摘要。

卡片提供“拒绝 / 改一下 / 确认”三种动作。确认后在对话和右侧证据层显示当前路径、内容/结果版本和不可变 receipt digest；重复提交同一确认摘要返回同一回执。

## 5. 验收与当前边界

专项测试覆盖：命令语法、无确认零写入、错误确认拒绝、同名目标冲突、缺失父目录、源版本漂移、创建和重命名的原子边界后恢复、重复提交幂等、API 同会话创建后重命名，以及前端预览/确认/回执。静态检查继续要求 Ruff、mypy、Vue type-check、production build、全前端测试和工作台 UI 静态检测通过。

最终验证：工作区 Runtime、Capability/Plan、migration 与统一 Workbench API 四组共 63 项后端用例全部通过；其中联合运行发现的两处 Capability 精确集合旧断言已更新并精确复跑通过。Ruff 全仓、mypy 220 个生产源码、Alembic 单一 `0037` head/autogenerate check 和 `uv lock --check` 通过。前端 22 个测试文件/152 项、Vue type-check、production build 与工作台源组件 finesse 静态检测 `p0: 0` 通过，`git diff --check` 无空白错误。本阶段没有自行打开用户页面做视觉断言。

当前仍不支持：

- 创建或重命名目录；
- 覆盖、删除、回收站或批量路径操作；
- 任意二进制、隐藏文件或扩展名；
- 跨卷/跨工作区 move；
- 从模型输出或网页内容直接获得确认；
- Shell、PowerShell、npm scripts 或自由 argv。

下一阶段可在相同确认/回执协议上增加多类 Artifact，或先为现有能力增加更自然但仍确定性的命令参数提取；不能绕过当前版本绑定和显式确认边界。

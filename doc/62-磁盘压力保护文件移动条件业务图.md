# 阶段 62：磁盘压力保护文件移动条件业务图

## 1. 本阶段目标

阶段 44 已提供条件边、内容寻址 branch decision 和 ready proof，阶段 48～60 已补齐数据库 admission、ready projection 与跨 API graph control，但公开业务请求仍只生成无条件图。本阶段注册首个真实、可从前端触发且不依赖模型写路径的条件业务图：

```text
inspect_capacity (computer.disk_usage, R0)
  ├─ used_percent <= maximum_used_percent -> move_file (file.move, R1 approval)
  └─ used_percent >  maximum_used_percent -> confirm_deferred (computer.disk_usage, R0)
```

阈值 100 可稳定触发 move 分支；阈值 0 在正常已使用磁盘上可稳定触发 defer 分支。两条分支都经过真实 Runner、Tool ledger、DAG ready projection 和 admission，不是测试 executor 或前端推断。

## 2. 受保护请求与固定图模板

新增结构化请求：

```json
{
  "kind": "disk_pressure_guarded_file_move",
  "source": "<用户明确选择的现有普通文件>",
  "destination": "<用户明确选择的同盘未存在目标>",
  "maximum_used_percent": 80
}
```

API 复用 `file.move` 的路径规范化和 no-overwrite/same-volume 校验。目标磁盘检查路径只能由规范化后的 `destination.parent` 派生，不能由模型、goal 或条件 resolver 自由提供。

固定 v2 图包含三个节点：

- `inspect_capacity`：读取目标目录所在磁盘的容量；
- `move_file`：只在 `disk_pressure_route=move` 时 ready；
- `confirm_deferred`：只在 `disk_pressure_route=defer` 时 ready，再次只读采样并明确完成“安全推迟”路径。

未选分支由既有 reducer 以 `branch_not_selected` 转为 `skipped`。move 分支仍保留 `receipt_bound_reverse` 补偿策略；两个只读节点没有补偿策略。

## 3. 受信证据与分支决定

`DiskPressureBranchDecisionResolver` 只接受：

- source node 为 `inspect_capacity` 且已持久化成功；
- decision key 精确为 `disk_pressure_route`；
- 图声明的 outcome 集合精确为 `defer/move`；
- terminal event 绑定确定性 call ID；
- Tool name/version/contract digest/status 精确匹配 `computer.disk_usage@1.0.0`；
- 输出通过 `DiskUsageOutput` 严格 Schema，且 resolved path 等于目标父目录。

resolver 对 Tool 输出摘要、terminal event ID/sequence、阈值、比较符、观测使用率和 outcome 计算 evidence digest。数据库 branch decision 继续由阶段 44 的 proof 覆盖 source revision/event、全部条件边和 evidence digest，并生成内容寻址 `decision_id`。

原始路径和 Tool 参数不写入 branch decision；模型不参与阈值比较，也不能生成、改写或补全 outcome。

## 4. 混合 R0/R1 Tool 账本与审批

原 v2 业务接线把 preparer 的 idempotency/risk 固定为 `file.move`。本阶段将这些字段改为来自每个节点的不可变 `ToolContract`：

- R0 磁盘节点创建独立 call/attempt/policy ledger，由精确 local-user disk metadata scope 自动允许；
- R1 move 节点只有在 branch decision 已提交、ready proof 已更新后才创建账本和一次性审批；
- defer 分支不会创建 `file.move` call 或写审批；
- Runner 执行、node claim、graph fence、admission permit 和终态 transition 仍使用原子命令。

策略新增独立 `allow_user_selected_disk_usage` 开关。它只允许 `local_user + builtin + computer.disk_usage` 的精确 R0 contract、单一 filesystem path resource、无副作用/网络/数据外发组合；模型 actor 或 contract 不匹配仍返回 `RESOURCE_SCOPE_DENIED`。

Dispatcher 增加默认关闭的 `stop_after_branch_decision`。业务编排启用它，使分支决定提交后先返回外层 preparer，为新选中的节点创建 Tool/policy/approval ledger，再进入 claim；避免 decision 与 claim 在同一 dispatcher 内跨越尚未建立的授权边界。通用 dispatcher 的既有行为保持不变。

## 5. 前端演示

任务表单新增“磁盘压力保护移动（条件图）”：

- 输入源、目标和 0～100 的最高磁盘使用率；
- 提交固定 `disk_pressure_guarded_file_move` 请求；
- 时间线明确标注 `effect.branch.decided` 与未选节点 skip；
- 任务快照显示“压力允许，进入移动审批”或“压力过高，已安全推迟写入”；
- 只有 move 路径出现原有的一次性审批卡。

前端只展示数据库事件中的 outcome，不在浏览器重新计算磁盘阈值或乐观推断分支。

## 6. 验证结果

新增覆盖：

- 阈值 100 真实触发 move，先有 R0 Tool 结果和 branch decision，再产生唯一 R1 审批与签名 commit receipt；
- 阈值 0 真实触发 defer，move 节点 skipped、复核节点 succeeded、源文件保持原位且无审批；
- 用户选择的 disk metadata scope 只有精确 local-user R0 contract 可通过，模型 actor fail closed；
- 前端请求 payload、阈值校验、分支摘要和事件标签。

## 7. 已知边界与下一步

- 当前条件是目标磁盘使用率阈值，不是文件大小/剩余空间容量规划；它证明受信条件业务链，不应被解释为完整存储容量保证。
- 分支证据使用已持久化 Tool terminal event 和内容摘要；通用 branch proof 仍按阶段 44 设计只保存 evidence digest，不保存原始路径或输出副本。
- defer 是成功执行“安全推迟”业务结果，不会自动排队重试或在磁盘压力下降后自行移动。
- 公开 `file_move_dag` 仍保留无条件通用 DAG 入口；本业务图使用独立固定 schema，未开放客户端自定义条件边。

下一阶段进入本地知识库最小只读闭环：先定义受控文档来源、内容寻址 artifact、解析/索引边界和可恢复检索证明，再考虑 MCP 接入；继续禁止模型生成写路径或任意执行代码。

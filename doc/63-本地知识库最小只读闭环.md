# 阶段 63：本地知识库最小只读闭环

## 1. 本阶段目标

在不引入云服务、目录扫描、任意解析器或模型写路径的前提下，建立首个可从前端触发的本地知识闭环：用户显式选择文本文件，后端只读导入为内容寻址 Artifact，检索前重新验证来源版本和数据库证明，只返回带行号与摘要证明的命中。

## 2. 受控来源边界

首版只接受单个现有普通文件：

- 扩展名只能是 `.md` 或 `.txt`；
- 必须是严格 UTF-8、非空、无 NUL 字节，最大 1 MiB；
- symlink、目录、二进制、未知格式和读取中发生变化的文件全部拒绝；
- 路径必须由用户在受保护 API/前端显式提交，不读取 goal 或模型输出；
- 导入仅调用文件元数据和 `read_bytes`，不修改、移动或锁定源文件，也不扫描父目录。

`source_version` 绑定规范路径、原始内容 SHA-256、字节数和 mtime ns。每次检索都会重新读取来源并比较该版本；来源缺失、不可读或变化时，旧分块 fail closed，不进入命中，并在 `stale_source_ids` 中提示重新导入。

## 3. 内容寻址存储与解析

Alembic `0027_local_knowledge` 新增：

- `knowledge_artifacts`：`artifact_id = art_<raw-byte-sha256>`，保存解析器/分块器版本、文本、字节数、分块数和 manifest digest；
- `knowledge_sources`：规范路径唯一，指向该来源当前 Artifact，并保存来源版本；
- `knowledge_chunks`：按行窗口确定性分块，保存 `Lx-Ly` locator、文本摘要和内容寻址 proof。

同一字节内容重复导入不会复制 Artifact 或 Chunk；同一路径变化后只更新当前指针，旧 Artifact 保留为不可变内容记录，但不会由当前来源检索返回。首版解析器是 `plain-text.v1`，分块器是最多 1200 字符的确定性行窗口，不执行宏、脚本、HTML、附件或外部引用。

## 4. 检索证明与 fail-closed

`POST /api/v1/knowledge/search` 使用本地确定性 Unicode 关键词计数，不调用模型或外部 embedding。检索前执行：

1. 分别读取 Source/Artifact 与完整 Chunk 集合，避免缺失分块被联表查询静默隐藏；
2. 重新计算 Artifact 内容摘要、ID、字节数、parser/chunker 版本、分块集合和 manifest；
3. 逐块重算 text digest、proof digest 与内容寻址 chunk ID；
4. 重新读取每个源文件并核对 `source_version`；
5. 仅对全部校验通过且来源仍为当前版本的分块排序和截断。

每条 Citation 绑定 query digest、source/source version、artifact manifest、chunk proof 和 score，生成 `retrieval_proof_digest`；整个响应再生成 `result_digest`。数据库 Artifact、元数据、Chunk 文本、证明或完整集合不一致时，API 返回 `409 KNOWLEDGE_PROOF_REJECTED`，不降级返回部分结果。

## 5. API 与前端

新增受本地 Bearer 会话和 Origin 中间件保护、禁止缓存的 API：

- `GET /api/v1/knowledge/sources`；
- `POST /api/v1/knowledge/sources:import`；
- `POST /api/v1/knowledge/search`。

前端导航启用“知识库”，提供显式路径导入、来源清单和本地检索。结果展示来源绝对路径、行 locator、文本片段和 retrieval proof 前缀；来源变化时提示重新导入。浏览器不自行读取磁盘、不重算证明，也不把查询放入 URL。

## 6. 验证结果

新增自动化覆盖重复内容寻址导入、来源列表、证明命中、来源变化失效、格式/二进制拒绝、完整 Chunk 集合删除后的稳定拒绝，以及 `0027 -> 0026 -> 0027` migration 往返与 metadata check。

最终门禁：Ruff 全仓通过；mypy 144 个生产源码通过；pytest 415 collected、403 passed、12 skipped、1 条既有第三方 warning；Alembic `0027` head/check 和 `0027 -> 0026 -> 0027` 往返通过；`uv lock --check` 通过；前端 18 文件/137 项测试、type-check 和 production build 通过。

## 7. 已知边界与下一步

- 当前是线性本地关键词检索，不含 FTS5、embedding、语义 rerank 或模型问答；
- 只支持 UTF-8 Markdown/文本，不支持 PDF、DOCX、网页、图片 OCR、目录 watch 或批量导入；
- Source 当前路径指针可更新但尚无删除/历史浏览 API；旧内容只是不再被检索，并未实现 retention；
- proof 用于检测数据库内容不一致，不替代数据库文件 ACL、备份、加密或外部签名根；
- Citation 是即时可重算证明，尚未把一次检索固化为持久化审计事件；
- 查询会线性验证当前全部知识分块，1 MiB 单文件和小规模来源是本阶段的明确容量边界。

下一阶段进入受控 MCP 接入前的协议与信任边界：先定义 Server 注册、能力声明、会话隔离、Schema 固定、超时/取消、审计与默认禁网策略，再选择一个只读本地 MCP 做最小闭环；不得把 MCP 响应直接视为 Tool 授权或写路径。

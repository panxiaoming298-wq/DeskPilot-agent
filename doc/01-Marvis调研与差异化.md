# 01. Marvis 调研与差异化定位

> 调研日期：2026-08-08。产品能力可能继续变化，进入代码阶段前应复核相关接口与下载要求。

## 1. 调研结论

腾讯 Marvis 适合作为产品方向参考：它把对话、文件理解、系统操作、应用/浏览器、端云协同和隐私模式组合成一个桌面助手。但公开资料不足以还原其真实内部实现，因此本项目只借鉴公开产品能力，不声称复现源代码或私有架构。

## 2. 证据分级

| 等级 | 含义 | 使用规则 |
| --- | --- | --- |
| A | 腾讯官方产品页面、协议或正式文档 | 可用于确认公开功能和平台支持 |

| C | 第三方体验、聚合站、论坛 | 只用于发现线索或用户痛点，不作为核心架构事实 |

## 3. 可确认的公开能力

根据 [Marvis 官方网站](https://marvis.qq.com/)（A 级证据），可以确认：

- 支持 Windows 10+ x64、macOS、Android 和 iOS 客户端。
- 提供效率模式和本地模式；官网明确描述本地模式“文件 0 上传”。
- 手机可连接电脑、查看任务执行画面并接管。
- 支持文件/图片内容搜索、图片 OCR、AI 图库和 AI 文档库。
- 支持自然语言查看电脑信息、修改部分系统设置。
- 支持本地文档、表格的理解、生成、润色、图表和格式转换。

腾讯云开发者社区的 [Marvis 技术百科](https://developer.cloud.tencent.com/techpedia/2612)（B 级证据）进一步描述了“1 个主 Agent + File、Computer、App、Browser、Search 5 个专业 Agent”的协作方式，以及敏感操作确认。由于官方首页未公开这些 Agent 的代码、协议和调度算法，本项目把它当作产品分工参考，而不是可验证的内部实现。

## 4. 值得借鉴的产品思想

### 4.1 统一自然语言入口

用户不需要记住文件名、设置入口或应用操作步骤。Agent 负责把目标映射到操作能力，这比“给出教程、用户自己点”更接近真正的任务完成。

### 4.2 专业能力域

按 File、Computer、App、Browser、Search 拆分职责，能限制每个 Agent 的工具集合和提示词范围，也方便独立测试。DeskPilot 延续该划分，但将安全策略和结果验证设计为独立的确定性系统组件。

### 4.3 本地优先与端云协同

文件索引、系统动作留在本地，复杂推理可选择云端。用户必须在 UI 中看见本次请求会发送哪些内容，而不是只提供一个模糊的“隐私模式”开关。

### 4.4 控制权交还用户

涉及删除、系统配置、账号、外部发布等操作时暂停并请求确认。DeskPilot 进一步要求审批与具体工具、参数、资源版本绑定，防止“确认 A，实际执行 B”。

## 5. 公开产品方向中的可改进空间

以下不是对 Marvis 私有实现的断言，而是桌面 Agent 这一产品类别普遍需要解决的问题：

| 问题 | 只做表面复刻的风险 | DeskPilot 方案 |
| --- | --- | --- |
| 过程透明度 | 只有“Agent 正在工作”动画，无法解释真实步骤 | 结构化计划、事件时间线、工具参数摘要、证据面板 |
| 长任务可靠性 | 进程或网络中断后整项重来 | 步骤检查点、幂等键、恢复与补偿 |
| 提示注入 | 网页/文档内容诱导 Agent 执行危险动作 | 不可信内容隔离、能力令牌、策略引擎最终裁决 |
| 模型锁定 | 换供应商后工具 schema/上下文行为失效 | 能力协商的 Model Gateway、共同子集与原生适配器 |
| 扩展成本 | 每加一个能力就修改 Supervisor | Tool Manifest、Agent Profile、MCP Adapter、注册表发现 |
| 质量无法证明 | 演示成功但没有回归数据 | 黄金任务集、轨迹回放、安全与成功率指标 |
| 过度多 Agent | 简单任务也多次调用模型，慢且贵 | 确定性快速路径 + 复杂任务图 |

## 6. DeskPilot 的差异化卖点

### 6.1 可恢复任务图

每个复杂任务变成带依赖关系的步骤图。步骤有输入、预期输出、风险、幂等性、重试策略和验证器。系统重启时从安全检查点继续，而不是重新问模型“之前做到哪了”。

### 6.2 Policy-as-Code

权限不是提示词中的一句“请小心”，而是独立规则：资源范围、工具风险、外部副作用、审批有效期、参数指纹和调用来源都参与判断。即使模型被提示注入，Runner 仍会拒绝越权。

### 6.3 模型能力协商

连接模型时建立能力档案：是否支持工具调用、严格 JSON、视觉、流式、上下文长度、并行工具调用。路由器根据任务需求选模型；能力不足时使用确定性解析或明确降级。

### 6.4 事件溯源与可回放

计划生成、工具请求、审批、执行结果、验证和终止原因形成追加式事件。开发者可用录制结果替换真实模型/操作系统，复现一次失败，这对面试展示比“漂亮聊天框”更有说服力。

### 6.5 证据优先输出

搜索结果保留 URL 和抓取时间，文件答案保留路径与页/段定位，系统操作保留操作前后快照。Verifier 根据证据判定任务是否真的完成。

## 7. 对比定位

| 维度 | 普通聊天机器人 | 简单自动化脚本 | DeskPilot |
| --- | --- | --- | --- |
| 自然语言理解 | 强 | 弱 | 强 |
| 本地实际执行 | 通常无 | 强但固定 | 受控执行 |
| 复杂任务规划 | 有限 | 固定流程 | 结构化任务图 |
| 风险审批 | 通常无 | 人工写逻辑 | 统一策略协议 |
| 故障恢复 | 对话级 | 依脚本而定 | 步骤检查点 |
| 可扩展性 | 模型工具绑定 | 改代码 | Tool/MCP/Agent 声明 |
| 可评测性 | 回答评分 | 单元测试 | 任务成功 + 安全 + 轨迹 |

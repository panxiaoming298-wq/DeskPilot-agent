# 00. 项目愿景、需求与范围

## 1. 项目定位

DeskPilot 是运行在用户 Windows 电脑上的“自然语言任务控制面”。它不只是回答“怎么做”，而是在获得授权后调用本地能力把任务做完，并向用户展示计划、证据、进度和结果。

2026-08-16 方向更新：DeskPilot 明确定义为“本地优先的通用任务 Agent”，不是只能操作本地文件的窄任务执行器。“本地优先”允许受控联网与云端模型，但运行真值、策略、工作区和用户控制留在本地。首个已接受纵向切片是 `research_to_html`：对话明确目标、联网研究、Claim 级引用、Task Workspace 生成 HTML、隔离浏览器验收后交付。边界见 [ADR-015](ADR-015-通用任务Agent产品边界与首个纵向切片.md)。

项目优先服务两个目标：

1. **真实可用**：完成文件、电脑状态、应用、浏览器、网络信息五类高频任务。
2. **求职可展示**：体现 Python 后端、系统设计、异步任务、状态机、LLM 工程、安全、测试与可观测性，而不是只有一段调用模型的 Demo。

## 2. 目标用户

首版目标用户是单机、单账户的 Windows 10/11 中文用户。典型用户不熟悉复杂路径、系统设置和自动化脚本，但愿意在敏感操作前进行确认。

### 2.1 核心用户故事

| 编号 | 用户故事 | 预期协作 |
| --- | --- | --- |
| US-01 | “找出下载目录里最近一个月的 Java 面试资料，按主题汇总” | File + Knowledge |
| US-02 | “检查为什么 C 盘空间不够，只给建议，先别删除” | Computer + File |
| US-03 | “打开 IDEA 和这个项目目录” | App + File |
| US-04 | “搜索上海 Java 应届岗位常见要求，给出处并形成报告” | Search + Browser + File |
| US-05 | “读取这几份 PDF，比较技术栈并输出 Markdown” | File + Knowledge |
| US-06 | “关闭占用内存最高的非系统应用” | Computer + App + Approval |
| US-07 | “安装指定 ID 的 PowerToys” | App + Policy + Approval；后期能力 |
| US-08 | “以后不要访问我的财务目录” | Policy + Preference Memory |
| US-09 | “查询某主题的最新公开资料，比较来源并制作一个可打开的 HTML 页面” | Conversation + Research + Artifact + Browser Verification |

## 3. 功能需求

### 3.1 对话与任务

- 支持多轮对话、附件/路径引用和上下文续问。
- 将自然语言请求分类为问答、只读检查、可逆修改、高风险动作或超范围请求。
- 复杂任务生成结构化 DAG 计划；用户可以在执行前修改或取消。
- 支持运行中事件、阶段进度、暂停、继续、取消、超时和失败重试。
- 最终答复必须区分“已经完成”“仅给建议”“失败/未执行”。

### 3.2 文件与文档

- 仅在授权根目录内枚举、按元数据过滤和读取文件。
- 支持 TXT、Markdown、代码、PDF、DOCX、XLSX、PPTX 和常见图片的文本提取。
- 支持全文检索、语义检索、引用原文件与页码/工作表位置。
- 文件写入采用临时文件 + 原子替换；移动/重命名提供冲突预览。
- 删除默认进入回收站，不提供绕过回收站的通用工具。

### 3.3 电脑与应用

- 查询 OS、CPU、内存、磁盘、网络、进程、启动项等信息。
- 通过已发现的应用注册表启动应用，不允许模型指定任意可执行文件。
- 关闭应用、修改设置、结束进程等动作需要按风险级别审批。
- 后续通过 WinGet 精确包 ID 安装/升级软件；禁止直接运行未知下载文件。

### 3.4 浏览器与搜索

- 搜索服务返回标题、URL、摘要、时间和来源。
- 浏览器 Agent 优先使用 DOM 与可访问性树定位，不依赖脆弱的屏幕坐标。
- 网页内容作为不可信数据，不能覆盖系统指令或直接授权工具调用。
- 登录、提交表单、下载文件、发布内容等动作单独标注风险。
- 输出研究结论时保留可点击来源和抓取时间。

### 3.5 模型与扩展

- 通过统一接口接入 OpenAI-compatible 云端 API 与 Ollama 本地服务。
- 启动时探测结构化输出、工具调用、视觉、上下文长度等能力。
- 内置工具和 MCP 工具都登记到 Tool Registry，并通过同一权限层。
- 新 Agent 主要通过声明、提示词、工具白名单和输出 schema 扩展。

### 3.6 研究与可编辑产物

- Search 与 Model Gateway 解耦，实际页面保存为可复核 `PageSnapshot`，主要事实保留 Claim 级 Citation。
- 每个创建型任务使用独立 Artifact Workspace；Agent 不能直接获得用户目录任意写权限。
- Artifact 修改形成不可变 Revision 和 PatchReceipt；导出或覆盖用户文件单独审批。
- HTML 先在无登录、默认断网的新浏览器 Context 中验收渲染、错误、网络和截图证据。
- 网页、搜索摘要、MCP 和上传内容始终是不可信数据，不能变成授权或 active 长期记忆。

## 4. 非功能需求

| 维度 | 目标 |
| --- | --- |
| 安全 | 默认最小权限；高风险操作零静默执行；提示注入不能直接触发本地副作用 |
| 可靠性 | 任务步骤持久化；进程重启后可恢复；非幂等步骤不盲目重试 |
| 性能 | 事件首屏及时；文件索引增量更新；大结果分页/摘要后进入模型上下文 |
| 可扩展 | Agent、Tool、Model、Store 使用稳定接口；插件失败不拖垮主进程 |
| 可观察 | 每个任务有 trace_id；记录计划、工具、模型、审批、错误和资源消耗 |
| 可测试 | LLM、OS、网络均可替换为 fake；任务轨迹可录制并确定性回放 |
| 隐私 | 明确展示数据是否离开本机；密钥进系统凭据库；日志默认脱敏 |
| 易用性 | 风险说明使用人话；用户始终能暂停/取消；不暴露冗长思维链 |

## 5. 范围分层

### 5.1 P0：必须完成

- 对话、状态机、任务事件与基础 UI。
- File/Search/Computer/App 的只读能力。
- Browser 的搜索与网页读取能力。
- 单 Task Artifact Workspace、静态 HTML 生成、隔离浏览器验收与显式导出。
- 云端 + 本地两类模型连接。
- R0～R3 风险分级、审批与审计。
- 20 个黄金任务集和自动化回归。

### 5.2 P1：增强竞争力

- 本地知识库、混合检索、引用定位。
- 可恢复任务 DAG、并发步骤和补偿动作。
- MCP stdio 接入、插件清单和健康检查。
- 成本/延迟/成功率仪表盘。
- 任务模板与可复用技能。

### 5.3 P2：毕业设计后的演进

- Tauri 桌面壳、系统托盘和全局快捷键。
- 定时任务、远程设备接入和端到端加密。
- 视觉电脑操作、跨应用复杂 GUI 自动化。
- PostgreSQL/Qdrant、团队账户和远程 Worker。

## 6. 明确不做

- 不复制腾讯商标、视觉素材、协议流量或逆向私有实现。
- 不宣称达到操作系统内核级控制；本项目是用户态本地服务。
- 不让 LLM 直接获得管理员权限或任意 shell。
- 不自动处理支付、验证码、银行、医疗等高风险事务。
- 不在 MVP 中自研大模型、OCR 引擎、浏览器内核或远程桌面协议。
- 不为了“多 Agent”把单步任务强行拆成多个模型调用。

## 7. 约束与假设

- 开发者以个人为主，时间和测试设备有限，必须控制系统能力范围。
- Windows 版本、应用 UI 和模型行为均可能变化，工具要有能力探测与明确错误。
- 本地小模型通常工具调用能力弱于云端模型，系统必须支持降级到确定性路由。
- 不同 OpenAI-compatible 服务只兼容共同子集，不能假设都支持 Responses API 或相同 JSON schema 行为。
- 用户负责合法使用网络信息和本地文件，系统仍应提供来源、权限和隐私提示。

## 8. 成功定义

项目完成不是“聊天窗口能回复”。完整闭环应满足：

1. 用户给出目标。
2. 系统判定风险和所需能力。
3. 用户看见计划与必要审批。
4. Agent 调用工具并持续报告进度。
5. 系统验证产物或状态变化。
6. 用户获得结果、证据和未完成项。
7. 开发者能从 trace 中解释每一步，并用测试复现失败。

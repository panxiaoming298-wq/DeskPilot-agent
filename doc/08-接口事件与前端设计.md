# 08. 后端接口、事件与前端设计

## 1. API 风格

- 资源管理和命令使用 REST。
- 长任务创建后立即返回，状态通过 WebSocket 推送。
- 所有写请求支持 `Idempotency-Key`，避免前端重试创建重复任务。
- API 路径以 `/api/v1` 版本化；Breaking change 新开版本。
- 时间使用 ISO 8601 UTC，ID 使用字符串，枚举值稳定。
- 错误采用 Problem Details 风格，包含可机器处理的 `code`。

## 2. 首期 REST API

### 2.1 会话与消息

| Method | Path | 作用 |
| --- | --- | --- |
| POST | `/api/v1/conversations` | 创建会话 |
| GET | `/api/v1/conversations` | 分页查询会话 |
| GET | `/api/v1/conversations/{id}` | 会话详情 |
| POST | `/api/v1/conversations/{id}/messages` | 发送消息并可创建任务 |
| DELETE | `/api/v1/conversations/{id}` | 预览/删除会话数据 |

### 2.2 任务

| Method | Path | 作用 |
| --- | --- | --- |
| POST | `/api/v1/tasks` | 直接创建任务 |
| GET | `/api/v1/tasks/{id}` | 当前状态与计划 |
| GET | `/api/v1/tasks/{id}/events?after_seq=` | 断线补拉事件 |
| POST | `/api/v1/tasks/{id}:pause` | 请求在安全点暂停 |
| POST | `/api/v1/tasks/{id}:resume` | 从检查点恢复 |
| POST | `/api/v1/tasks/{id}:cancel` | 取消未开始步骤并终止可取消工具 |
| POST | `/api/v1/tasks/{id}:retry` | 对允许的失败步骤重试 |
| GET | `/api/v1/tasks/{id}/artifacts` | 查询任务产物 |

控制命令请求体可省略，或使用 `{"reason":"用户可读原因"}`。成功返回最新 `Task` 快照；非法状态转换返回 `409 TASK_TRANSITION_NOT_ALLOWED` 并附 `current_status`、`target_status`、`allowed_statuses`。同一 API 进程没有可恢复检查点时返回 `409 TASK_RUNTIME_UNAVAILABLE`。

### 2.3 审批

| Method | Path | 作用 |
| --- | --- | --- |
| GET | `/api/v1/approvals?status=pending&task_id=` | 按状态/任务查询审批 |
| GET | `/api/v1/approvals/{id}` | 最终参数与风险预览 |
| POST | `/api/v1/approvals/{id}:approve` | 仅批准本次精确绑定的调用 |
| POST | `/api/v1/approvals/{id}:reject` | 拒绝并可说明原因 |

审批 POST 必须携带服务端返回的 `preview_hash`，当前只接受 `scope="once"`。摘要不一致时接口返回 `409 APPROVAL_STALE`，前端刷新完整预览，而不是复用旧确认。当前持久化、事务和 Runner 授权语义见 [Policy / Approval 执行前授权主干](28-Policy-Approval执行前授权主干.md)。

### 2.4 配置与能力

| Method | Path | 作用 |
| --- | --- | --- |
| GET | `/api/v1/model-providers` | 查询无密钥 descriptor、启用/默认状态与有效健康缓存；不触发网络 |
| GET | `/api/v1/model-providers/{id}/health` | 按需执行有界、缓存且脱敏的单 Provider 健康探测 |
| POST（后续） | `/api/v1/model-providers` | 创建模型配置 |
| GET | `/api/v1/tools` | 工具及健康/风险 |
| GET | `/api/v1/agents` | Agent Profile |
| GET/POST | `/api/v1/mcp-servers` | MCP 配置与启停 |
| GET/POST | `/api/v1/allowed-roots` | 文件授权目录 |
| GET/PATCH | `/api/v1/privacy-settings` | 模式和数据规则 |
| GET | `/api/v1/health` | 本地服务健康 |

当前 Provider health 使用短期 TTL、同 Provider single-flight 和全局并发上限。公共快照不包含 endpoint、credential reference 或 adapter 的内部 `detail`；disabled Provider 返回 `409 MODEL_PROVIDER_DISABLED` 且不执行探测。Provider 列表额外返回持久化公开投影的 `catalog_version/imported_at`。完整实现见[Provider 只读 API 与健康探测缓存实现](19-Provider只读API与健康探测缓存实现.md)和[Provider Catalog 持久化与启动导入实现](20-Provider-Catalog持久化与启动导入实现.md)。

## 3. 请求与响应示例

创建任务：

```http
POST /api/v1/tasks
Idempotency-Key: 01J...
Content-Type: application/json

{
  "conversation_id": "conv_...",
  "goal": "检查 C 盘空间，只分析，不删除任何文件",
  "privacy_mode": "local_preferred",
  "constraints": ["read_only"]
}
```

响应：

```json
{
  "task_id": "tsk_...",
  "status": "created",
  "event_stream": "/api/v1/events?task_id=tsk_...",
  "created_at": "2026-08-08T08:00:00Z"
}
```

错误：

```json
{
  "type": "urn:deskpilot:problem:path-not-allowed",
  "title": "目录未授权",
  "status": 403,
  "code": "PATH_NOT_ALLOWED",
  "detail": "目标不在允许访问的目录中",
  "instance": "/api/v1/tasks/tsk_...",
  "trace_id": "trc_...",
  "recoverable": true,
  "next_action": "open_allowed_roots_settings"
}
```

## 4. WebSocket 协议

当前阶段按任务连接：`GET /api/v1/ws/tasks/{task_id}?after_seq=12`。浏览器通过 `Sec-WebSocket-Protocol` 同时请求 `deskpilot.v1` 与 `deskpilot.auth.<session-token>`，服务端只回选 `deskpilot.v1`；令牌不进入 URL、访问日志或 Referer。

未来需要单连接复用多个任务时，建立认证连接后客户端发送订阅：

```json
{"type":"subscribe","task_ids":["tsk_..."],"after_seq":{"tsk_...":12}}
```

事件 envelope：

```json
{
  "event_id": "evt_...",
  "task_id": "tsk_...",
  "seq": 13,
  "type": "tool.started",
  "timestamp": "2026-08-08T08:00:02Z",
  "trace_id": "trc_...",
  "payload": {"step_id":"s1","tool":"computer.disk_usage"}
}
```

关键事件类型：

- `task.status_changed`
- `task.classified`
- `plan.proposed` / `plan.updated`
- `step.started` / `step.progress` / `step.completed` / `step.failed`
- `model.started` / `model.usage` / `model.failed`
- `tool.requested` / `tool.started` / `tool.completed` / `tool.failed` / `tool.cancelled` / `tool.unknown`
- `approval.required` / `approval.resolved` / `approval.expired` / `approval.invalidated`
- `artifact.created`
- `warning.raised`
- `task.completed` / `task.failed` / `task.cancelled`

事件至少一次投递，前端按 `(task_id, seq)` 去重。WebSocket 只推送小事件，artifact 通过 REST 分页读取。

`model.started` 只包含 request ID、角色、Provider、model、protocol、location 和输出 Schema 名；默认不把完整 prompt/messages 放入任务事件。`model.usage` 使用归一化 Token、finish reason 和 latency，`model.failed` 使用稳定错误码与 retryable 标志。

`tool.requested` 只公开参数与幂等键摘要，不保存原值。`tool.unknown` 表示调用可能已经执行但缺少可信终态，固定 `retryable=false`、`requires_reconciliation=true`，随后任务进入 `failed`；前端不得把它渲染为普通可重试失败或自动触发 Resume。

## 5. 本地 API 安全

- 默认绑定 `127.0.0.1`，不监听局域网。
- 每次 API 进程启动生成高熵 session token；开发阶段只允许精确白名单 Origin 或同源 Fetch Metadata 的前端通过 `/api/v1/session` 获取，响应禁止缓存。
- REST 除健康检查和会话引导外均要求 `Authorization: Bearer <token>`；写请求还必须提供白名单 Origin 或可信同源请求元数据。
- WebSocket 必须同时通过精确 Origin 校验和子协议令牌认证，拒绝把 token 放入查询参数。
- 错误采用 RFC 9457 字段与 `application/problem+json`，稳定扩展字段为 `code`，参数错误可附 `errors[]`。
- 会话 token 仅保存在前端内存；收到 401 或 WebSocket 4401 后清除并重新引导。
- 桌面壳使用严格 CSP，不允许任意远程脚本。
- WebSocket 重连、REST 重试均不改变审批或任务语义。
- API 文档在开发环境开启，发布环境默认关闭或仅本地开发开关可见。

## 7. 核心交互

### 7.1 执行时间线

用户看到的是可审计摘要，不是模型私有思维链：

```text
✓ 已理解目标：只分析 C 盘，不删除文件
✓ 已读取磁盘容量（只读）
● 正在统计授权目录中的大文件
○ 将生成清理建议
— 删除动作不在本任务授权范围内
```

每个工具步骤可展开查看：输入摘要、风险、开始/结束时间、结构化结果、证据和错误。敏感值默认遮罩。

### 7.2 审批卡

审批卡不能只有“允许/拒绝”：

- 标题：“将关闭 IntelliJ IDEA（可能存在未保存内容）”。
- 目的：“用户要求释放内存”。
- 目标：应用名、PID、窗口标题摘要。
- 后果：是否可撤销、是否可能丢数据。
- 选项：拒绝 / 仅本次允许；高风险不提供永久允许。
- 如果参数变化，旧卡作废并显示差异。

### 7.3 取消和接管

- 输入框的“停止”只取消可取消阶段；UI 明确显示“正在等待安全停止”。
- 浏览器遇到登录、验证码、支付或复杂页面时进入 `waiting_input`，用户接管。
- 用户完成后点击“继续”，系统重新观察页面状态，不假设用户完成了某一步。

## 8. 前端状态管理

Pinia store 建议按领域划分：

- `conversationStore`：会话和分页消息。
- `taskStore`：task snapshot、按 seq 归并事件、DAG。
- `approvalStore`：待审批和 preview_hash。
- `artifactStore`：元数据与按需预览。
- `settingsStore`：模型、隐私、目录、MCP。
- `connectionStore`：WebSocket 状态、游标、退避重连。

服务端状态以事件为准。前端可乐观更新“已发送消息”，但不能乐观显示“工具已执行”或“审批成功”。

## 9. UI 质量要求

- 中文为默认语言，技术 ID 放在高级详情。
- 色彩之外使用图标/文字区分成功、警告、失败，满足基本可访问性。
- 所有长任务都显示最后事件时间、当前状态和取消入口。
- 路径、URL、错误可复制；密钥不可回显。
- 计划图有列表模式，避免 Mermaid/图形不可访问。
- 首期桌面宽屏优先，但审批和任务状态在窄窗口仍可操作。
- 空状态提供可直接运行的安全示例任务。

## 10. 前后端契约管理

- FastAPI OpenAPI 是 REST 契约源，生成 TypeScript client/types。
- WebSocket 事件使用共享 JSON Schema，并生成前端判别联合类型。
- CI 检查 schema breaking change 和未生成代码。
- 前端使用 Mock Service Worker/固定事件录制独立开发，不依赖真实模型和本机工具。
- 每个任务状态和错误 code 必须有前端展示与恢复动作。

# 阶段 79：受控工作区文件读取与精确替换

阶段 78 已把研究、知识库和 MCP 统一到对话 Route Catalog，但 Agent 仍不能读取当前项目文件，也不能把一个明确修改落到项目中。阶段 79 增加第一条真实的项目工作能力：用户在对话中指定工作区相对路径，Agent 可以读取受限文本文件；对单个文本片段的修改先生成版本绑定预览，经用户确认后再原子提交。

本阶段已实现。它让 DeskPilot 从“会研究和查询”前进到“能在受控项目里查看和修改一个文件”，但仍不是 Codex 等价物：没有 Shell、动态 Python、删除、目录操作、批量补丁、任意覆盖、包安装或模型自由规划。

## 1. 默认无文件权限

新增配置：

```text
DESKPILOT_CONVERSATION_WORKSPACE_ROOT=D:\path\to\project
```

未配置时，`workspace_file_read@1` 和 `workspace_file_replace@1` 都返回 unsupported，不会退化为当前目录或用户主目录。配置根目录必须真实存在、是目录且不是符号链接。

所有用户路径必须是根目录内的相对路径。运行时拒绝绝对路径、`..`、符号链接、目录、非 UTF-8 文件、超过 256 KiB 的文件和未允许扩展名。首版只开放 `.md/.txt/.py/.json/.yaml/.yml/.toml/.html/.css/.js/.ts/.vue`。

## 2. 两条固定语法 Route

首版刻意使用可解释的确定性语法，不让模型从任意自然语言中猜写入目标：

```text
读取工作区文件：README.md
在工作区文件 README.md 中把 "旧文本" 替换为 "新文本"
```

`workspace_file_read@1` 为 R0，只读取一个文件并返回规范化相对路径、字节数、内容摘要、稳定版本摘要和文本内容。

`workspace_file_replace@1` 为 R1，只允许一个非空旧文本在目标文件中恰好出现一次。零次或多次匹配都拒绝，不猜测位置，也不支持正则表达式。Route 参数、候选判定、Capability manifest 和结果摘要继续写入阶段 78 的 `TurnRouteRecord`，Contract/Plan/Run 仍是同一套服务器真值。

## 3. 预览、确认、提交

精确替换分为两个阶段：

1. 预览读取当前文件，绑定原版本摘要、拟写内容摘要、字节数、旧文本、新文本和 confirmation digest；文件不发生变化。
2. 用户在对话流内检查“要做什么、影响什么、凭什么”和前后文本，提交 confirmation digest。
3. 提交前再次读取文件；若版本已变化，拒绝写入并要求重新预览。
4. Windows 使用 `ReplaceFileW` 在同一文件系统内原子替换，并把被覆盖的精确旧文件保留为隐藏安全备份。
5. 目标内容、旧版本备份和新版本全部复核后，才生成 `deskpilot.workspace-edit-receipt.v1` 并把 Run 标记为 succeeded。

备份名由 Task ID 派生，不能由用户控制，也不会静默覆盖已有文件。回执包含原版本、新版本、内容摘要、备份相对路径、提交时间和 receipt digest。

## 4. 崩溃恢复

外部文件效果和数据库事务无法成为同一个原子事务，因此提交前先把 Route/Node 持久化为 `running`。重试时使用提升后的 fencing token 接管，并按文件事实恢复：

- 目标仍是原版本且暂存文件不存在：重新暂存并提交；
- 目标仍是原版本且暂存内容与预览一致：继续跨越原子替换边界；
- 目标是拟写内容且备份精确等于原版本：重建成功回执；
- 目标、备份或暂存内容无法证明上述状态：返回 unknown/failed，保留安全文件供人工检查，不冒充成功。

使用 Windows `ReplaceFileW` 而不是“先复制、再 `os.replace`”，是为了让系统在原子边界同时捕获真正被覆盖的文件；否则外部编辑器在复制和替换之间写入的内容可能丢失。非 Windows 平台当前拒绝提交，只保留安全读取与预览。

## 5. 对话界面

阶段 77/78 的对话工作台不增加新的后台页面：

- 读取 Route 自动执行，右侧展示文件内容、版本和摘要；
- 替换 Route 停在 `needs_user_action`，在当前 Run 内展示前后文本和确认按钮；
- 提交中、错误、成功、禁用、键盘焦点和移动端状态使用同一组件；
- 成功后在对话和证据区同时展示安全备份路径与提交回执；
- 错误确认、版本漂移或路径越界均不修改目标文件。

## 6. 验收结果

自动化验收覆盖：

1. 相对路径读取、内容/版本/结果摘要；
2. 绝对路径与 `..` 越界拒绝；
3. 多匹配替换拒绝；
4. 预览阶段零文件效果；
5. 错误 confirmation digest 零文件效果；
6. 成功原子替换、旧文件安全备份和不可变回执；
7. 原子边界前已有暂存文件与边界后数据库未落盘两种恢复；
8. 同一 confirmation 重复提交返回同一事实；
9. 前端审批卡不进入安全自动推进，只有用户点击才调用 commit API。

配置和实现默认 fail closed。阶段 79 没有新增数据库迁移，复用阶段 78 的 Route result manifest 保存预览与回执。

最终验证：后端完整 pytest 收集 498 项并以退出码 0 完成；Ruff 全仓通过，mypy 通过 215 个生产源码，Alembic autogenerate check 与 `uv lock --check` 通过。前端 22 个测试文件/147 项、Vue type-check 和 production build 通过；`finesse-ui` 静态检测对工作台与八状态预览均为 `p0: 0`。按界面技能约束，本次未擅自打开用户页面或截屏。

# 11. 分阶段开发路线与验收标准

> 本文记录项目早期 0～7 高层路线，历史内容保留用于解释已有工程演进。阶段 68 之后的权威实施顺序已经由 [ADR-015](ADR-015-通用任务Agent产品边界与首个纵向切片.md)重排为阶段 69～75，见[《多 Agent 运行时、记忆与验证实施路线》](多Agent运行时记忆与验证实施路线.md)。早期 12～16 周估算基于较窄 MVP，已失效；阶段 73 的长期记忆/遗忘已完成，当前进入阶段 74 可证明上下文压缩与重建。

## 1. 总体节奏

早期按个人业余开发估算完整求职版需要 **12～16 周**；扩大到通用对话、联网研究、Artifact 工作区与浏览器验收后，该日历估算已废止。仍然有效的原则是持续交付可运行纵向闭环：

```text
对话输入 -> 任务状态 -> 策略 -> 工具 -> 验证 -> 事件/UI -> 测试
```

每个阶段结束都必须有可演示功能和自动化验收。若时间不足，优先保证 P0 闭环、安全和评测，削减桌面壳、视觉自动化、远程控制等 P2 功能。

## 2. 阶段总览

| 阶段 | 建议时间 | 交付结果 | 退出条件 |
| --- | --- | --- | --- |
| 0. 设计确认与技术 Spike | 3～5 天 | ADR、关键依赖验证 | 用户确认范围和选型 |
| 1. 工程骨架与事件主干 | 1～2 周 | API/Web/DB/Runner/Fake Model | 可创建任务并看到事件 |
| 2. 只读 MVP 闭环 | 2 周 | File/Computer/App 只读与快速路径 | 5 个任务稳定完成 |
| 3. 任务图与模型网关 | 2 周 | 规划、专业 Agent、云/本地模型 | 复杂任务可恢复 |
| 4. 副作用、安全与浏览器 | 2～3 周 | 审批、文件写、应用、Search/Browser | 安全矩阵通过 |
| 5. 知识库与记忆 | 2 周 | 增量索引、混合检索、引用 | 文档问答有可验证引用 |
| 6. MCP、评测与可观测 | 2 周 | MCP stdio、黄金任务、trace 面板 | 指标可重复 |
| 7. 求职发布与打磨 | 1～2 周 | 安装/演示、视频、简历材料 | 陌生机器可按说明运行 |

## 3. 阶段 0：设计确认与 Spike

### 工作项

- 确认项目正式名称、Vue 3、Python 3.12+、MVP 边界，以及 ADR-014 的“自研领域 Runtime + 只读图投影”边界。
- 建立 ADR 目录并记录关键决策。
- 在目标 Windows 机器验证 Python/uv、Playwright、pywin32、pywinauto。
- 用 3 种文档验证 PDF/DOCX/XLSX 提取与中文编码。
- 验证一个云端 OpenAI-compatible Provider 和一个 Ollama endpoint。
- 对候选向量实现做安装、增删改查和 1 万 chunk 小测试。
- 验证 Tool Runner IPC 候选方案的认证与取消。

### 验收

- 输出 spike 结果表：成功、限制、版本和替代方案。
- 任何关键依赖失败都有不阻塞 P0 的 fallback。
- 不开始大规模编码前由用户确认本目录方案。

## 4. 阶段 1：工程骨架与事件主干

### 后端

- 初始化 uv workspace、分层 package、Ruff/mypy/pytest。
- 定义 Task/Step/Event/ToolCall/Approval 领域模型。
- SQLite、Alembic、Repository、Event Store、Outbox。
- FastAPI health、task create/get、events 补拉。
- WebSocket 订阅、游标、断线重连协议。
- Fake Model、Fake Runner 和第一个状态机测试。

### 前端

- Vue 3 + TS + Pinia + Router。
- 工作台骨架、任务状态、事件时间线、连接状态。
- OpenAPI client 和事件类型生成。

### 验收场景

用户发送“测试任务”，Fake Model 生成固定步骤，Fake Runner 返回结果；刷新页面后仍能看到完整事件，WebSocket 断线重连不重复展示。

## 5. 阶段 2：只读 MVP 闭环

### 工作项

- Tool SDK、Registry、schema 校验、Runner 请求认证。
- `file.list/stat/read_text/search`。
- `computer.system_info/disk_usage/process_list`。
- `app.discover` 和只启动测试应用的受控 `app.launch`。
- 意图规则和单工具快速路径。
- Artifact 元数据与分页预览。
- 授权目录设置与路径安全测试。

### 五个必须通过的任务

1. 查询系统与磁盘信息。
2. 在测试目录找到指定文件。
3. 读取 Markdown 并生成摘要。
4. 枚举并启动登记的测试应用。
5. 请求未授权目录时明确拒绝。

### 验收

- 工具不在 API 进程执行。
- 每次调用有 task/step/call/event 链路。
- 自动化测试只操作临时目录和测试进程。
- 用户能取消一个慢工具。

到这里已经有第一个可演示版本；不要等全部 Agent 做完才第一次演示。

## 6. 阶段 3：任务图与 Model Gateway

### 工作项

- ModelProvider port、OpenAI-compatible、Ollama、Fake adapter。
- 能力探测和 ModelCapabilities。
- Prompt Package、结构化计划 schema、Plan Validator。
- 自研领域状态 reducer、PostgreSQL 恢复协议、budget/循环保护，以及版本化 `GraphViewProjection`；不建立 LangGraph checkpoint 第二真值。
- Supervisor + File/Search/Knowledge 基础 Agent Profile。
- 并发调度、资源锁、重试分类、恢复 reconciliation。

### 验收场景

“读取三份测试文档，提取主题并生成比较 Markdown”：系统生成 DAG，文档解析可并行，生成步骤等待输入完成；API 在中间重启后从检查点继续，不重复解析已完成 artifact。

### 质量门

- 非法 JSON 只修复一次。
- 模型生成未知工具或有环计划时本地拒绝。
- 本地模型能力不足时按隐私设置降级，不静默上云。

## 7. 阶段 4：副作用、安全与浏览器

### 工作项

- Policy Engine、R0～R4、审批实体与一次性授权。
- 文件新建、移动、回收站和 dry-run manifest。
- 应用正常关闭；强杀继续禁用。
- Search Provider 适配。
- Playwright Worker：open/extract/click/fill，submit 保持 R3。
- Prompt injection 标签、URL/SSRF 过滤、下载隔离。
- 审批卡、参数差异、过期/换参 UI。

### 验收场景

- 移动 3 个测试文件：预览 → 同意 → 执行 → 哈希验证 → 可补偿。
- 审批后替换源文件，旧授权失效。
- 测试网页含恶意提示，Agent 只提取内容且不调用越权工具。
- 表单填入测试数据但不提交；提交请求显示精确目标和 R3 审批。

### 安全门

任何审批绕过、路径越界或提示注入导致副作用，都视为阶段未完成。

## 8. 阶段 5：知识库与记忆

### 工作项

- 授权目录扫描、Watcher、reconciliation。
- PDF/DOCX/XLSX/PPTX/Markdown 提取器。
- 结构化切块、FTS5、embedding adapter、向量索引。
- 混合召回、RRF、权限复核、引用 locator。
- 知识库 UI、索引进度、失败文件、空间占用。
- 会话/偏好/权限记忆管理。

### 验收

- 源文件修改后增量更新，删除后旧片段不可检索。
- 回答至少能定位 PDF 页码、Excel 工作表/范围或文本行号。
- LOCAL_ONLY 使用本地 embedding/模型，网络捕获显示无云端请求。
- 用户能查看并删除记忆，权限记忆不会被模型自动放宽。

## 9. 阶段 6：MCP、评测与可观测

### 工作项

- MCP stdio host、server 生命周期、schema 导入和权限映射。
- 一个自建只读示例 MCP server。
- 黄金任务 YAML runner、trace record/replay。
- OpenTelemetry trace、结构化日志、Provider/工具指标。
- 评测面板：成功率、安全、延迟、Token/费用。
- 故障注入：429、Runner 崩溃、WebSocket 断线、MCP 异常。

### 验收

- 新 MCP server 默认禁用，启用前展示命令、目录、网络和工具。
- MCP 自称 read-only 不能覆盖本地风险下限。
- 20 个黄金任务可一键运行并生成版本化报告。
- 核心成功率、安全指标和失败分类可以复现。

## 10. 阶段 7：求职发布与打磨

### 工作项

- 首次启动向导和 safe defaults。
- 诊断包、数据清理、错误恢复文案。
- Windows 全新用户环境安装 smoke test。
- 可选 Tauri 壳；若影响稳定性则保留浏览器发布形态。
- 架构图、GIF/截图、3～5 分钟演示视频。
- README 写入真实测量指标、硬件和模型配置。
- 完成简历 bullet、面试问答、已知限制和 roadmap。

### 验收

- 按 README 从干净环境启动成功。
- 无 API key 时仍能用 Fake/本地安全演示。
- 演示脚本在断网时有离线录制/fake 后备。
- 仓库不含密钥、私人路径、私有文件和不可再现结果。

## 11. P0/P1/P2 优先级

### P0：没有就不能称为完成

- 端到端任务状态机、独立 Runner、权限目录。
- 云/本地模型 adapter，至少各验证一个。
- File/Computer/App/Search/Browser 的精选能力。
- 审批、审计、取消、失败和恢复。
- 前端计划/事件/审批/结果。
- 黄金任务与安全测试。

### P1：显著提升竞争力

- 混合检索和精确引用。
- MCP stdio、插件 manifest。
- 轨迹回放、成本/成功率面板。
- Prompt/Tool/Agent 版本管理。
- 文件写入补偿和资源版本校验。

### P2：时间足够再做

- Tauri 壳、系统托盘、全局快捷键。
- 视觉 computer-use 和复杂 GUI。
- 定时任务、远程设备、移动端。
- 多用户、多租户、云端队列。
- 在线插件市场。

## 12. Definition of Done

每个功能完成必须同时满足：

- [ ] 用户场景和成功条件明确。
- [ ] schema、风险、错误和取消语义明确。
- [ ] 正常路径与至少一个失败/拒绝测试。
- [ ] 事件能在 UI 正确展示且断线可恢复。
- [ ] 日志与 trace 可定位，敏感字段已脱敏。
- [ ] 相关文档/OpenAPI/事件 schema 已更新。
- [ ] 在 Windows 实机或 CI 对应环境验证。
- [ ] 不引入未说明的权限或隐私变化。

“模型偶然运行成功一次”不满足 Definition of Done。

## 13. 开始代码后的前 10 个任务

1. 创建 ADR-001～004 并锁定设计选择。
2. 初始化 Python workspace 和 Vue 工程。
3. 定义 Task/Step/Event 最小领域模型和状态测试。
4. 实现 SQLite migration、Event Store 与 Outbox。
5. 实现 POST/GET task 和 event replay API。
6. 实现 WebSocket 订阅和 Vue 事件时间线。
7. 实现 Fake Model/Fake Runner 的完整闭环。
8. 定义 Tool Contract、Registry 和 Runner IPC spike。
9. 实现第一个 R0 工具 `computer.disk_usage`。
10. 实现授权根目录和 `file.list`，补路径对抗测试。

按此顺序可以很早得到可运行主干，后续能力只是向主干添加适配器。

## 14. 进度控制

- 每周只选择一个纵向里程碑，限制同时进行的工作。
- 每周末录制 1～2 分钟真实进度，防止长期只有文档/重构。
- 每阶段记录成功率、已知失败和下一阶段风险。
- 连续两周未打通的 P1 依赖降级或替换，不让单个库拖垮项目。
- 任何新功能若需要扩大权限，先更新安全文档和测试，再实现。

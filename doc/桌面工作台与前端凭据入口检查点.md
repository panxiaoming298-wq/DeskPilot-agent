# 桌面工作台与前端凭据入口检查点

日期：2026-08-29

## 结论

本检查点把桌面端从一次性品牌开场改为长期使用的对话工作台，并把云 Provider 的 API Key 配置收进产品界面。它只改善本机配置和操作体验，不授予真实模型调用、Production Admission、cloud activation 或 116C-B 执行权限。

## 工作台改造

- 默认直接进入 Agent 会话，不再用全屏封面阻断工作区。
- 删除鲨鱼视频、海洋海报、HUD、扫描线、全局滚动动画和持续环境动效。
- 视觉语言改为中性石墨色、低饱和鼠尾草绿、系统无衬线字体与等宽证据文本；布局以紧凑侧栏、对话画布和上下文面板为主。
- 保留有意义的状态反馈，并适配 `prefers-reduced-motion`；移动宽度下控制项保持可触达且页面不横向溢出。
- 这是面向编码 Agent 的安静编辑器工作台，不复制 Codex 的商标、品牌资产或逐像素界面。

## API Key 产品流程

正常桌面流程为：

1. 用户在 Provider 设置页选择 OpenAI、DeepSeek、阿里云百炼、自定义兼容服务或离线 Fake Provider。
2. 对云 Provider，用户在密码输入框中输入 API Key。
3. 前端通过已认证的本机 API 把 Key 交给后端；后端写入当前 Windows 用户的 Credential Manager。
4. Provider 配置只保存 credential identifier，运行时再由后端解析；Key 不写入 catalog、日志、浏览器存储或响应正文。

用户不需要为桌面产品手工修改 Windows 环境变量。既有 environment credential resolver 继续保留给开发、CI 或兼容部署，但常规界面不会引导用户选择它。

## 安全语义

- 状态接口只返回 `available`、`missing` 或 `invalid`，从不返回秘密值。
- 写接口只接收秘密并返回脱敏状态；输入框提交后立即清空，留空表示保留现有 Key。
- 删除要求精确确认头；已启用的 Provider 不允许从界面直接删除其 Key。
- 凭据标识受 Windows credential identifier 规则限制，底层长度和写入错误继续 fail closed。
- 对外错误只返回稳定、脱敏的错误语义，不泄露 Key、系统路径或底层异常详情。

## Provider 预设

- OpenAI：Responses API，默认模型 `gpt-5.6-luna`，凭据标识 `OPENAI_RESPONSES`。
- DeepSeek：OpenAI-compatible Responses，默认模型 `deepseek-v4-flash`，凭据标识 `DEEPSEEK`。
- 阿里云百炼：OpenAI-compatible Responses，默认模型 `qwen3.8-max`，凭据标识 `BAILIAN`；Base URL 仍要求用户填写其北京业务空间实际地址，避免猜测控制台配置。
- 自定义：用户明确填写名称、模型、Base URL 和 Windows credential identifier。
- Fake：继续作为默认离线验证入口，不要求凭据。

预设只是减少配置错误，不会自动启用 Provider，也不会触发健康检查、模型请求或费用。

## 当前授权边界

本检查点没有读取或保存任何真实 Key，没有访问 OpenAI、DeepSeek 或百炼，没有创建 live permit，也没有运行 12 次 Provider 探针或 20 任务 / 60 trial。真实模型 capture、Production Admission、cloud activation 和 116C-B 仍保持阻断；后续即使用户从界面保存 Key，也必须经过原有独立授权门。

## 验收范围

- 后端：状态、写入、删除、确认不匹配、错误脱敏和凭据后端不可用均有 API 测试。
- 前端：请求体不泄漏、删除确认头、预设映射、留空保留、写后清空和禁用删除均有组件/API 测试。
- 浏览器：桌面主工作台、Provider 设置弹窗以及 320/375/414/768 像素宽度已人工检查；没有真实凭据或 Provider 请求。

# 阶段 73：长期记忆、确认、冲突与遗忘

阶段 73 在阶段 72 的短期 Context 数据面上增加跨会话长期记忆。长期记忆仍不是任务、权限、Policy 或 verified edge 的真值，不会解锁执行节点。

## 已完成

- `MemoryProposal`、版本化 `MemoryItem`、可见 `MemoryConflict`、无明文 tombstone 和实际 `MemoryUsage` 账本。
- 支持 `preference`、`restrictive_permission`、`user_confirmed_fact`、`verified_episode` 与 `skill_template`。
- 用户明确偏好、收紧型限制和带 verified delivery 的技能模板可直接生效；用户事实、verified episode 与所有 Agent 提案必须确认。
- 同 scope、同 kind、同 key 的异值不会覆盖。全部相关版本进入 `conflict`，用户选择一个版本后其余版本删除密文并留下墓碑。
- TTL 到期、冲突和删除状态不会被 Context Builder 召回。
- value 使用与 Provider 运行配置相同的本机保护器保存；普通数据库列、日志、trace、ContextManifest、tombstone 和导出墓碑都没有明文。
- Research Model Turn 可召回 Agent Contract 明确允许的 active 长期记忆。敏感记忆不会发送给 cloud Provider。
- ContextManifest 继续只保存来源、版本、摘要、分类、token 与出境决定；`MemoryUsage` 记录实际 task、invocation、Agent、Provider、location 和时间。
- verified Delivery 完成后只生成带 30 天 TTL 的 episode 提案，不会自动 active。
- 新增长期记忆证据账本前端，可查看来源、版本、TTL、冲突、Agent/Provider 使用记录，并执行新建、确认、拒绝、修订、删除、冲突解决和导出。
- 新增 `0034_long_term_memory` migration 与阶段 73 独立 CI gate。

## 优先级与信任边界

Context Builder 的固定顺序是当前 Task Contract 与 Handoff、当前任务短期记忆和消息、已确认长期记忆、verified claim 与外部数据。当前指令和任务约束始终在长期记忆之前。

`restrictive_permission` 只是一条额外限制。它不调用 Policy 写接口，也不能改变审批要求。即使内容声称“无需审批”，Tool Policy、Approval 和 Runner 授权证明仍按原有 reducer 执行。

网页、MCP 输出和子 Agent 文本没有长期记忆写路由。内部 Agent 提案必须绑定可验证的 `AgentResultRecord` 与 digest，且状态固定为 `pending_confirmation`。verified episode 必须绑定有效 `DeliveryManifest`。

## 验收覆盖

- 客户端不能伪造 external source；不存在或摘要错配的 AgentResult/Delivery proof 会 fail closed。
- 事实与 Agent/episode 提案不会直接 active。
- 冲突项全部停止召回，用户显式解决后只有选中版本恢复 active。
- 过期与删除项停止召回；删除清除密文，导出墓碑不含 key/value 明文。
- 实际 Research ContextManifest 包含长期记忆来源，并生成可见 Agent/Provider usage ledger。
- 前端危险删除使用两次显式确认，并说明历史 Context 不能被撤回。

## 明确非目标

- 不实现 embedding、向量索引或语义召回。Memory 与 RAG 保持独立。
- 不实现摘要压缩、CompactionSnapshot 或历史重建；这些属于阶段 74。
- 不让 Memory 修改 Task/Event/Tool/Policy 真值，也不让它绕过阶段 71 verified edge。

# 阶段 116B：持久并行编码循环第四检查点

## 1. 检查点结论

116B 第四个代码检查点已将受控 Git branch/commit 纵切接入同一个 `workspace_coding_loop` TaskLoop。固定测试通过后，系统不再直接进入 Final/Delivery，而是由服务器准备 exact Git 预览，等待第二次用户确认，再创建服务器命名的新分支与单个提交。提交只能包含已经 Patch/Test 证明链绑定的文件，随后以类型化 `git_commit` ResultRef 解锁最终验收与 Delivery。

这一检查点闭合了“读取 → 提案 → 确认 Patch → 测试/修复 → 确认 Git → 提交 → 交付”的本地持久链。当前图仍是服务器封存的精确双文件任务；2～8 文件动态绑定、依赖变更、自由 Shell、自动 push、真实 cloud 模型质量和生产激活仍不在本检查点内。

## 2. 固定图与两次确认

```text
                  coordinate_coding
                         |
             +-----------+-----------+
             |                       |
      inspect_primary          inspect_secondary
             |                       |
   plan_primary_patch       plan_secondary_patch
             \                       /
              +---- verified join ---+
                         |
              apply_patch (confirm #1)
                         |
                  run_fixed_test
                         |
                commit_git (confirm #2)
                         |
                 final_acceptance
                         |
                      delivery
```

- Coordinator 现在只能确认七个业务节点，唯一输出节点从 `run_fixed_test` 改为 `commit_git`；最终验收和 Delivery 仍由服务器 Reducer 管理。
- 第一次确认仍绑定 exact Patch staging/changes/revision，第二次确认单独绑定 Git HEAD、分支、工具链、文件和回滚备份证明；两者不共享或推断授权。
- `TaskLoopCapabilityApproval` 仍使用原有持久表，但按精确 `schema_version + schema_digest` 区分 Patch 与 Git 预览。Patch 确认入口不能消费 Git 预览，反之亦然。
- 测试非 `passed` 时 `commit_git` 保持 pending；一次已知失败 Repair 通过后才解锁 Git 预览。

## 3. Git 授权预览与边界

`GitCommitPreview` 是不可变、内容寻址的单次授权，包含：

- exact Task ID、项目路径、Git 工具摘要、仓库身份和 expected HEAD；
- 原分支与服务器命名的 `codex/deskpilot-<task-prefix>` 新分支；
- 服务器固定提交消息，模型和 API 调用方均不能提供 Git argv、环境变量或作者身份；
- 2～8 个排序且唯一的编码文件内容证明。当前 coding DAG 恰好使用其中两个；
- 每个文件恰好一个隐藏 DeskPilot rollback backup 证明。备份不进入 commit，但必须在确认和执行时保持完全一致；
- `hooks_disabled=true`、`signing_disabled=true`、`push_disabled=true` 和整个 confirmation digest。

准备只接受 standalone project-root Git 仓库：`.git` 必须是项目内真实目录，top-level/git-dir/common-dir 必须精确回到该项目，external object store、worktree pointer、alternates、symlink/junction/reparse point 均拒绝。工作树状态必须恰好是授权文件的 unstaged modification 和对应隐藏备份；额外 staged/untracked/deleted/renamed/copied 状态全部 fail closed。

## 4. 固定 Git 执行与可恢复回执

Git 进程只执行服务器固定子命令，并同时固定以下边界：

- 关闭 hooks、commit signing、push、pager、external diff、fsmonitor、replace objects、交互输入和自动 CRLF 转换；
- 全局/系统 Git config 不可见，本地 `core.attributesFile` 被强制指向空设备，仓库 `.gitattributes` 与 `.git/info/attributes` 直接拒绝，防止 clean filter 借 `git add` 执行外部命令；
- 作者/提交者固定为 DeskPilot 本地身份，分支、路径和 message 均只从已确认预览获取。

执行可对账而不盲目重放：

1. 原分支 + exact unstaged 状态：创建新分支，只暂存授权文件，再提交；
2. 已创建 target branch 但未暂存：重验完整预览后从该边界续接；
3. 已在 target branch 暂存 exact 文件：确认 index 没有额外内容后只执行提交；
4. HEAD 已是候选提交：不再提交，而是验证 parent/tree/message/path/blob/original branch/status 后重建同一回执。

任一不在上述集合的 partial state、HEAD/branch/index/worktree/config/toolchain/path/content/backup 漂移均拒绝。`GitCommitReceipt` 绑定 expected HEAD、commit/tree OID、原/目标分支、message digest、文件证明、提交时间和固定 guard；验证通过后才生成 `git_commit` ResultRef。

## 5. Workbench、持久化与兼容

- `TaskLoopExecutionRead` 和统一 `TaskWorkbenchRead` 新增可选 `workspace_git_commit`，等待时显示脱敏 Preview，消费后显示 Receipt。
- 新增 `commit_workspace_git` Workbench action 与对应确认端点，仅接受当前 execution revision 和 confirmation digest。本检查点不新增前端页面，但前端协议类型与 API client 已跟进。
- Delivery 新增脱敏 target branch、expected HEAD、commit OID、receipt digest、push-disabled 和 rollback-available 证据，并移除 `git_commit_not_created` 风险；`local_fake_model_quality_unproven` 仍保留。
- 新交付清单升为 `deskpilot.workspace-coding-delivery.v2`。已完成的第三检查点 v1 仍按严格的“6 节点 + `run_fixed_test` 输出 + 无 Git 证据”规则只读；v2 必须是“7 节点 + `commit_git` 输出 + 唯一 Git 证据”，不使用模糊回填。
- 预览、审批和回执仍保存在现有 JSON manifest 和 TaskLoop attempt/result 表；没有新列或第二套 Git 步骤状态机，因此 Alembic head 保持 `0059_workspace_coding_amendments`。

## 6. 诚实边界

- 当前 Route 仍由服务器预绑定恰好两个文件，不是模型自由选择 2～8 文件，也不是运行中修改 DAG。
- 新分支与 commit 只留在本地隔离测试仓库；没有 remote 查询、fetch、push、PR 或自动合并。
- 回执证明 rollback backup 仍存在，但本检查点没有新增自动 Git rollback/revert API。
- 没有开放依赖安装、锁文件改写、网络、凭据、自由 executable/argv/env 或任意 Shell。
- 全部验收只证明 LOCAL-only/Fake 运行时语义。115B 真实 Candidate/Judge、代码出站、费用、真人评审和激活授权仍缺失，cloud-only cohort 继续 disabled，本结果不是 116C 真实模型质量结论。
